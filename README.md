# Практическая работа №1 — TPC-H Q18

В практической работе выполнен вариант 3 — запрос Q18 из набора TPC-H. Для этого был собран локальный lakehouse на Iceberg.

## Масштаб данных

Для работы выбран масштаб `sf1`. Он подходит для запуска на одном компьютере: таблица `lineitem` содержит около 6 млн строк, поэтому запрос проверяется на заметном объёме данных без чрезмерной нагрузки на компьютер.

## Ход работы

1. Описала сервисы lakehouse в `docker-compose.yml` и запустила их через Docker Compose. Использовала MinIO для хранения Parquet-файлов, PostgreSQL для метаданных Lakekeeper, Lakekeeper как Iceberg-каталог, Trino для SQL-запросов и Superset для просмотра данных.
2. Создала таблицы Bronze из исходных таблиц TPC-H. Для Bronze использовала формат Parquet со сжатием ZSTD.
3. В Silver сгруппировала строки `lineitem` по заказам и оставила заказы, у которых суммарное количество товара больше 300. При соединении с данными клиента нормализовала имя через `trim` и исключила пустые значения.
4. В Gold сохранила итоговый результат Q18, отсортированный по сумме заказа. На масштабе `sf1` запрос вернул 57 строк.
   Сверила витрину с исходным запросом через `EXCEPT` в обе стороны: различий нет.
5. Сравнила Parquet и ORC с кодеками GZIP и ZSTD: измерила размер трёх таблиц Bronze, время их записи и медианное время Q18 по четырём запускам после разогрева. Parquet/GZIP оказался самым компактным (181,40 МБ), ORC/ZSTD записался быстрее всего (6,663 с), а время Q18 было близким для всех вариантов (0,393–0,415 с).
6. Проверила изменение схемы Iceberg, добавив колонку в Silver, и чтение результата Gold из предыдущего snapshot.
7. Подключила Superset к Trino и проверила чтение таблицы Bronze запросом `SELECT count(*) FROM customer;`. Результат — 150 000 строк.

## Файлы проекта

- `docker-compose.yml` — конфигурация сервисов.
- `sql/layers.sql` — создание таблиц Bronze, Silver, Gold и копий Bronze со сжатием GZIP.
- `sql/benchmark_tables.sql`, `sql/benchmark_q18.sql`, `sql/benchmark_sizes.sql` — скрипты для расширенного сравнения Parquet/ORC и GZIP/ZSTD.
- `sql/q18.sql` — запрос Q18 к исходным таблицам TPC-H.
- `sql/q18_bronze.sql` — запрос Q18 к таблицам Bronze в Iceberg.
- `sql/q18_check.sql` — проверка совпадения результата Gold с исходным Q18.
- [`отчет.md`](отчет.md) — подробный отчёт по практической работе.

Результаты сравнения форматов PARQUET и ORC со сжатием GZIP и ZSTD приведены в `отчет.md`. Скрипты `sql/benchmark_tables.sql`, `sql/benchmark_q18.sql` и `sql/benchmark_sizes.sql` позволяют повторить запись, запросы и подсчёт размера файлов.
